# Webpack: từ source code đến trình duyệt

Muốn hiểu Webpack, hãy bắt đầu bằng **một project chạy được**, không phải một danh sách tùy chọn cấu hình rời rạc.

Ví dụ xuyên suốt là ứng dụng React có nút đếm. Bài viết giải thích **vì sao cần từng file và chúng nối với nhau thế nào**. Source đầy đủ nằm trong trình xem riêng, không trải dài trong bài.

<SourceRef project="webpack-react-demo" variant="button">Mở toàn bộ source · React cơ bản</SourceRef>

Bấm **Source code ở góc dưới bên phải** để mở drawer, hoặc bấm tên file trong bài để tới đúng đoạn code. Bạn có thể đọc và cuộn bài bên cạnh source, chuyển file, chọn phiên bản, copy file hoặc copy link. Bấm **Thu source**, **×** hoặc **Esc** để thu drawer; mở lại sẽ giữ file vừa xem.

**Chưa dùng Vue, router hay Module Federation.** Các phần đó nằm trong [Webpack nâng cao: React shell và Vue remote](/web/04-webpack-react-shell-vue-remote).

## 1. Nhìn kết quả trước khi đọc config

Chúng ta tự viết những file bên trái. Webpack tạo file bên phải khi build:

```text
BẠN VIẾT                            BUILD TẠO RA

webpack-react-demo/                 webpack-react-demo/dist/
├── package.json                    ├── index.html
├── webpack.config.cjs              ├── main.<hash>.js
├── tsconfig.json                   └── main.<hash>.js.map
├── index.html
└── src/
    ├── main.tsx
    ├── App.tsx
    ├── styles.css
    └── env.d.ts
```

`<hash>` chỉ là ký hiệu minh họa. **Source là nguyên liệu; `dist` là kết quả đem phục vụ cho browser.** Không tự tạo hoặc sửa `dist/main...js`.

| <SourceRef project="webpack-react-demo" file="tsconfig.json" /> | TypeScript kiểm tra/chuyển đổi code theo quy tắc nào? | TypeScript, trực tiếp hoặc qua ts-loader |

## 2. Chạy ví dụ trên máy

Dùng **Node.js 22.12+ và npm**. Source thật nằm trong repository tài liệu, ở `examples/webpack-react-demo/basic`.

Nếu đã clone repository, chạy từ thư mục gốc:

```bash
cd examples/webpack-react-demo/basic
npm install
npm run dev
```

Nếu chỉ đang đọc website, tạo một thư mục `webpack-react-demo` riêng, mở Source Explorer và copy tám file theo đúng cấu trúc ở phần 1. Sau đó chạy cùng các lệnh `npm install` và `npm run dev` trong thư mục đó.

Mở `http://127.0.0.1:5173/`. Bạn phải thấy tiêu đề **React chạy qua Webpack**, số đếm ban đầu là 0 và nút tăng bộ đếm.

### Lệnh đó thực sự chạy gì?

Mở <SourceRef project="webpack-react-demo" file="package.json">scripts trong package.json</SourceRef>:

```text
npm run dev   → webpack serve ... --mode development
npm run check → tsc --noEmit
npm run build → npm run check && webpack ... --mode production
```

npm chỉ chạy chuỗi trong `scripts`, đồng thời cho phép tìm CLI đã cài ở `node_modules/.bin`. Nó không tự biết ứng dụng dùng Webpack, React hay Vue.

Packages trong ví dụ chia thành ba nhóm:

- **Giao diện:** `react`, `react-dom`.
- **Build và dev server:** `webpack`, `webpack-cli`, `webpack-dev-server`, `html-webpack-plugin`.
- **Chuyển đổi và kiểu:** `typescript`, `ts-loader`, `css-loader`, `style-loader`, các package `@types`.

npm tạo `node_modules` và `package-lock.json`; không tự viết chúng. Nên lưu lockfile để những lần cài tiếp theo dùng `npm ci`.

## 3. HTML và code React nối với nhau thế nào?

Mở <SourceRef project="webpack-react-demo" file="index.html" />. Phần quan trọng là:

```html
<div id="root"></div>
```

Đây chỉ là chỗ trống trong DOM. Nó **không tải React và không tự render giao diện**.

Tiếp theo, mở <SourceRef project="webpack-react-demo" file="src/main.tsx" />. File này:

1. Import API `createRoot`, component `App` và stylesheet.
2. Tìm phần tử `root` trong HTML.
3. Gọi `createRoot(element).render(<App />)`.

`root` là tên do chúng ta chọn; quan trọng là ID trong HTML khớp với `getElementById` trong code.

### `App.tsx` chứa gì?

<SourceRef project="webpack-react-demo" file="src/App.tsx">Xem component App</SourceRef> để thấy state `count`, dòng chữ hiển thị và nút tăng bộ đếm.

Khi người dùng bấm nút, **React cập nhật state và DOM**. Webpack không build lại ứng dụng vì người dùng bấm nút. Nó chỉ tham gia pipeline build/development, không điều khiển state của ứng dụng.

### Tại sao HTML source không có script?

<SourceRef project="webpack-react-demo" file="webpack.config.cjs" region="html">HtmlWebpackPlugin trong config</SourceRef> lấy HTML làm template, rồi thêm script trỏ tới bundle đã build. Minh họa:

```html
<script defer src="/main.abc123.js"></script>
```

`defer` giúp script chạy sau khi HTML đã parse xong. Plugin tạo thẻ script; **code gọi React mới render giao diện**.

Không thêm `<script src="./src/main.tsx">`: browser không tự hiểu TypeScript và TSX.

## 4. Đọc config Webpack theo thứ tự

<SourceRef project="webpack-react-demo" file="webpack.config.cjs" variant="button">Mở config đầy đủ để đối chiếu</SourceRef>

Không cần nhớ tất cả tùy chọn ngay. Lần theo năm nhiệm vụ dưới đây.

### 4.1. `entry`: bắt đầu đọc source từ đâu?

<SourceRef project="webpack-react-demo" file="webpack.config.cjs" region="entry">Xem cấu hình entry</SourceRef>

```js
entry: './src/main.tsx',
```

Webpack đọc `main.tsx`, gặp import rồi tiếp tục tìm các module liên quan:

```text
main.tsx
├── react-dom/client  → package trong node_modules
├── ./App             → src/App.tsx
│   └── react         → package trong node_modules
└── ./styles.css      → src/styles.css
```

Đó là **dependency graph**: bản đồ module nào cần module nào.

`main.tsx` là điểm bắt đầu vì config chọn nó, không phải tên đặc biệt. Đổi tên thành `start.tsx` thì sửa `entry`, không sửa HTML để tải source mới.

### 4.2. `resolve`: import đang trỏ tới file nào?

<SourceRef project="webpack-react-demo" file="webpack.config.cjs" region="resolve">Xem resolve.extensions</SourceRef>

`extensions: ['.tsx', '.ts', '.js']` giúp `import './App'` tìm được `App.tsx` dù không ghi đuôi.

**Tìm thấy file chưa có nghĩa là hiểu được nội dung file.** Thêm `.tsx` vào `extensions` không tự biên dịch TSX; vẫn cần bước tiếp theo.

### 4.3. `module.rules`: chuyển đổi nội dung thế nào?

<SourceRef project="webpack-react-demo" file="webpack.config.cjs" region="loaders">Xem các rule TypeScript và CSS</SourceRef>

```text
App.tsx
  → ts-loader gọi TypeScript
  → JavaScript
  → Webpack đóng gói cùng dependencies

styles.css
  → css-loader
  → style-loader
  → code chèn CSS khi bundle chạy trong browser
```

Trong `test: /\.tsx?$/`, `x?` nghĩa là có hoặc không có chữ `x`, nên rule khớp cả `.ts` và `.tsx`.

`exclude: /node_modules/` chỉ bỏ qua việc chạy **rule ts-loader đó** trên các file tương ứng. React vẫn được đóng gói, không bị loại khỏi ứng dụng.

Mảng `use: ['style-loader', 'css-loader']` có luồng chuyển đổi thông thường từ **phải sang trái**. Ví dụ này không tạo CSS riêng trong `dist`; CSS được đưa vào trang qua JavaScript.

<SourceRef project="webpack-react-demo" file="src/env.d.ts">Khai báo import CSS</SourceRef> chỉ giúp TypeScript chấp nhận loại import này. Nó không đọc CSS và không thay thế loader.

### 4.4. `output`: tạo file ở đâu và tên gì?

<SourceRef project="webpack-react-demo" file="webpack.config.cjs" region="output">Xem toàn bộ output</SourceRef>

| Tùy chọn | Công việc |
| --- | --- |
| `path` | Ghi vào thư mục `dist` trên máy build |
| `filename` | Đặt tên initial JavaScript chunk, ví dụ `main.<hash>.js` |
| `chunkFilename` | Đặt tên JS chunks tải bổ sung; phần 8 sẽ thử |
| `clean` | Dọn output cũ trong thư mục build |

`main` là tên entry mặc định khi `entry` là một chuỗi. Hash giúp URL phân biệt nội dung giữa các bản build. **Không có quy tắc một source file → một output file.**

Ba cấu hình đường dẫn cần tách biệt:

- `output.path`: đường dẫn thư mục trên **ổ đĩa**.
- `HtmlWebpackPlugin.publicPath: '/'`: tiền tố **URL** của script được chèn vào HTML.
- `output.publicPath: 'auto'`: runtime suy ra base URL để tải thêm chunk/asset.

Browser cần URL, không cần biết `/home/user/project/dist` trên máy build. Nếu deploy dưới `/demo/`, phải xem lại public paths; `/main.js` vẫn trỏ tới gốc domain, không tự thành `/demo/main.js`.

### 4.5. Những phần bao quanh pipeline

Mở lại <SourceRef project="webpack-react-demo" file="webpack.config.cjs" /> để đối chiếu:

- **`.cjs`:** Node.js đọc config theo CommonJS, nên dùng `require`, `module.exports`, `__dirname`, dù package có `"type": "module"`.
- **`context: __dirname`:** entry tương đối được tính từ thư mục config. Import `./App` bên trong `main.tsx` vẫn tính từ module đang import.
- **`mode`:** CLI truyền development hoặc production; config dùng nó để chọn cả source map phù hợp.
- **`target: 'web'`:** sinh runtime hướng tới browser; không tự thêm mọi polyfill.
- **`devServer`:** phục vụ app ở cổng 5173; ví dụ dùng reload toàn trang, chưa cấu hình React Fast Refresh.

Config chạy trong **Node.js**, không phải code React chạy trong browser.

## 5. TypeScript có config riêng để làm gì?

<SourceRef project="webpack-react-demo" file="tsconfig.json" variant="button">Mở tsconfig.json</SourceRef>

Webpack config quyết định pipeline; TypeScript config quyết định cách kiểm tra và chuyển đổi TS/TSX bên trong pipeline đó.

| Tùy chọn | Vai trò |
| --- | --- |
| `target: "ES2020"` | Mức cú pháp JavaScript TypeScript xuất ra; khác Webpack target |
| `lib` | Kiểu cho API DOM/JavaScript; không cài polyfill |
| `module: "ESNext"` | Giữ import/export để Webpack xử lý tiếp |
| `moduleResolution: "Bundler"` | Kiểm tra import theo quy tắc phù hợp với bundler |
| `jsx: "react-jsx"` | Chuyển JSX thành lời gọi React JSX runtime |
| `strict` | Bật nhóm kiểm tra kiểu chặt chẽ |
| `sourceMap` | Liên hệ JavaScript do TypeScript tạo với source gốc |
| `include: ["src"]` | Chọn source để TypeScript kiểm tra |

Ví dụ không đặt `noEmit: true` trong file vì ts-loader cần TypeScript trả về JavaScript cho Webpack. Riêng `npm run check` truyền `--noEmit`, nên chỉ kiểm tra kiểu.

Đừng chạy `npx tsc` rồi kỳ vọng có website hoàn chỉnh: TypeScript không thay Webpack gom dependencies, xử lý CSS và tạo HTML.

## 6. Dev và build khác nhau ở đâu?

```text
TRONG NODE.JS
npm → Webpack đọc config → build → phục vụ hoặc ghi output

TRONG BROWSER
HTML → tải bundle → main chạy → React render App
```

**Webpack CLI không chạy trong browser.** Bundle có thể chứa code hỗ trợ do Webpack sinh ra, gọi là **Webpack runtime**; đó không phải toàn bộ công cụ build.

- `npm run dev`: dev middleware thường phục vụ output trong bộ nhớ. Không thấy `dist` đổi không có nghĩa app chưa build.
- `npm run build`: kiểm tra kiểu, sau đó build production và ghi file vào `dist`. Không tự khởi động production server.

Chạy trong thư mục ví dụ:

```bash
npm run check
npm run build
ls dist
cat dist/index.html
```

Bạn sẽ thấy HTML tham chiếu bundle, không tham chiếu `App.tsx`:

```text
main.tsx ────────────┐
App.tsx ─────────────┤
React / React DOM ───┼──→ main.<hash>.js
CSS + style code ───┘
```

Đây là hình dung cho cấu hình hiện tại, không phải mọi project Webpack.

File `.js.map` hỗ trợ debug; `.LICENSE.txt`, nếu có, chứa thông báo license. Hai loại này không phải script cần chèn vào HTML.

Thử phục vụ output đã build:

```bash
npx --yes http-server@14 dist -p 4173 -c-1
```

Mở `http://127.0.0.1:4173/`. Đừng nhấp đúp `dist/index.html`: ví dụ dùng URL script từ gốc website và cần phục vụ qua HTTP. Static server trên đủ cho app này, không mặc định giải quyết SPA deep-link fallback nếu sau này thêm router.

## 7. Ba thay đổi nhỏ để tự kiểm chứng

Khôi phục code sau mỗi thử nghiệm. Source Explorer luôn giữ bản mẫu để đối chiếu.

| Thử thay đổi | Kết quả và điều cần hiểu |
| --- | --- |
| Đổi `id="root"` thành `id="app"` trong <SourceRef project="webpack-react-demo" file="index.html" /> nhưng giữ code tìm element | Build có thể thành công, nhưng app báo không tìm thấy `#root`. Đây là lỗi runtime. |
| Bỏ rule CSS trong <SourceRef project="webpack-react-demo" file="webpack.config.cjs" region="loaders" /> rồi chạy lại dev server | Webpack không xử lý được CSS. Khai báo type không thay loader. |
| Đổi `useState<number>(0)` thành `useState<number>('sai kiểu')` trong <SourceRef project="webpack-react-demo" file="src/App.tsx" /> | `npm run check` báo lỗi kiểu; `npm run build` dừng ở bước check. |

Ví dụ giữ chế độ type-check mặc định của ts-loader. Nếu project khác bật `transpileOnly`, không được mặc định rằng dev build vẫn kiểm tra kiểu đầy đủ.

## 8. Hiểu `bootstrap` và chunk qua phiên bản thứ hai

Ứng dụng ban đầu chạy được mà **không cần bootstrap**. Bây giờ mở phiên bản mới:

<SourceRef project="webpack-react-demo" snapshot="async-bootstrap" file="src/main.tsx" variant="button">Xem phiên bản · Thêm async bootstrap</SourceRef>

Hai thay đổi duy nhất so với bản cơ bản:

1. Code khởi động React được chuyển sang <SourceRef project="webpack-react-demo" snapshot="async-bootstrap" file="src/bootstrap.tsx" />.
2. `main.tsx` chỉ còn dynamic import để tải bootstrap.

```tsx
void import(
  /* webpackChunkName: "bootstrap" */
  './bootstrap'
).catch(console.error);
```

**`bootstrap` không phải file Webpack tự sinh.** Nó là source do chúng ta viết, tên do chúng ta chọn. Config vẫn dùng `entry: './src/main.tsx'`.

Static import khai báo dependency của module. Dynamic import trả Promise và, trong cấu hình này, tạo ranh giới tải riêng. Comment `webpackChunkName` chỉ dẫn đặt tên chunk lúc build.

Để chạy snapshot thứ hai, từ thư mục gốc repository:

```bash
cd examples/webpack-react-demo/async-bootstrap
npm install
npm run build
npx --yes http-server@14 dist -p 4173 -c-1
```

Nếu static server trước đó vẫn dùng cổng 4173, hãy dừng nó trước. Nếu tự tạo project từ website, chỉ cần thay `main.tsx` và thêm `bootstrap.tsx` theo phiên bản mới, rồi build lại.

Mở DevTools → **Network** → bật **Disable cache** → reload:

```text
index.html
  └── main.<hash>.js
        ├── bootstrap.<hash>.js
        └── có thể có chunk dependencies mang tên ID số
```

Số chunk phụ thuộc graph và tối ưu. File `327.<hash>.js` mang chunk ID, không phải thiếu source `327.tsx`.

### Vì sao tách rồi mà vẫn tải ngay?

Vì `main` gọi `import('./bootstrap')` ngay khi chạy. **Tách chunk không đồng nghĩa với chờ người dùng tương tác.**

HTML không cần script cho mọi async chunk: runtime yêu cầu phần còn thiếu khi `import()` chạy. Chunk đã được tạo lúc build; browser không biên dịch TypeScript ở bước này.

Async bootstrap hữu ích trong một số cấu hình Module Federation, nhưng không bắt buộc với mọi React app. Bản cơ bản đã chứng minh điều đó.

## 9. Muốn sửa một thứ, mở file nào?

| Muốn làm gì? | Mở ở đâu? |
| --- | --- |
| Sửa component, state | <SourceRef project="webpack-react-demo" file="src/App.tsx" /> |
| Sửa giao diện CSS | <SourceRef project="webpack-react-demo" file="src/styles.css" /> |
| Sửa tiêu đề tab hoặc DOM root | <SourceRef project="webpack-react-demo" file="index.html" /> |

| Đổi thư mục hoặc tên output | <SourceRef project="webpack-react-demo" file="webpack.config.cjs" region="output">output</SourceRef> |
| Đổi cách kiểm tra/chuyển TypeScript | <SourceRef project="webpack-react-demo" file="tsconfig.json" /> |

Sau khi sửa config, nên dừng và chạy lại dev server. Thêm dependency cần cài package; chỉ viết tên loader vào config không làm nó tự xuất hiện.

Chỉ cần nhớ: **package.json chọn lệnh → config nối pipeline → entry dẫn tới source → loaders chuyển đổi → Webpack tạo output → browser tải output → React render.**
